# TG fan channel

Бот стежить за Instagram (пости й сторіс), X і YouTube та публікує нове у Telegram-канал:
медіа, текст, транскрипцію, переклад, автора, посилання на першоджерело і підпис каналу.
База даних не потрібна: стан зберігається у файлах `state/*.json`.

## Де що працює

| Платформа | Де запускати | Як отримує дані | Вартість | Ризик блокування |
|---|---|---|---|---|
| YouTube | GitHub Actions | публічний RSS | безкоштовно | немає (Shorts можуть прийти як прев'ю) |
| X | GitHub Actions | офіційний API | приблизно $0.005 за прочитаний пост | немає |
| Instagram | домашній ПК | сесія окремого акаунта | безкоштовно | **є** |

Instagram винесено на домашній ПК, бо із серверних IP GitHub він, найімовірніше, швидко вимагатиме
перевірку або заблокує вхід. Цей спосіб порушує правила Instagram, тому жодних гарантій немає.
Використовуй лише окремий акаунт, який не шкода втратити. Якщо ПК вимкнений, бот пропустить запуск, але
наздожене пости та сторіс, які ще доступні (сторіс живуть 24 години).

## 1. Telegram

1. Створи бота в [@BotFather](https://t.me/BotFather) і скопіюй токен.
2. Додай бота в адміністратори каналу з правом публікації.
3. Дізнайся свій числовий ID в [@userinfobot](https://t.me/userinfobot) і напиши своєму боту `/start`.
   Сюди приходитимуть попередження про блокування.
4. Заповни `channel` та `accounts` у [config.yaml](config.yaml).

## 2. Файл із секретами

Скопіюй `.env.example` у `.env` і заповни. Файл `.env` не потрапляє на GitHub.

## 3. Перевірка

Команди виконуй у папці проєкту. Цей запуск нічого не надсилає, лише показує пости:

```bash
.venv\Scripts\python.exe -m bot --platforms youtube --dry-run
```

Цей запуск справді надсилає найновіший пост кожного YouTube-каналу, щоб подивитись, як він виглядає:

```bash
.venv\Scripts\python.exe -m bot --platforms youtube --send-latest 1
```

## 4. X (необов'язково)

Створи застосунок на [console.x.com](https://console.x.com), поповни баланс на мінімальну суму й скопіюй
Bearer Token. Без токена X просто пропускається (у журналі буде помилка, запуск позначиться як невдалий).
Якщо X поки не потрібен, задай на GitHub змінну `PLATFORMS` зі значенням `youtube` (див. крок 5).
Ціни звір у консолі перед поповненням, вони змінюються.

## 5. GitHub Actions (YouTube і X)

Публічний репозиторій рекомендований: для нього Actions безкоштовні. У приватному запуск кожні 15 хвилин
вичерпає безкоштовний ліміт. Секрети в обох випадках не видно, а от `config.yaml` і `state/` у публічному
бачать усі.

```bash
gh auth login
```

```bash
git add .
```

```bash
git commit -m "First version"
```

```bash
gh repo create tg-fan-channel --public --source . --push
```

Потім у репозиторії відкрий **Settings → Secrets and variables → Actions** і додай секрети
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `X_BEARER_TOKEN`.

Перший запуск запусти вручну: **Actions → Monitor → Run workflow**.

## 5б. Render (основний спосіб)

На Render бот працює постійно: на ручні пости відповідає одразу, а YouTube і X перевіряє кожні
10 хвилин (`CHECK_EVERY_MINUTES`). Пам'ять про опубліковані пости він зберігає в цьому репозиторії, бо
безкоштовний Render стирає файли при кожному перезапуску. Ці коміти мають позначку `[skip render]`,
тож бот через них не перезапускається.

1. **Токен GitHub для пам'яті.** [Створи токен](https://github.com/settings/personal-access-tokens/new):
   доступ лише до `Fan_bot_tg`, у **Repository permissions** постав **Contents: Read and write**.
2. **Сервіс.** На [render.com](https://render.com) увійди через GitHub, далі **New → Web Service** →
   `Fan_bot_tg` → **Language: Docker** → **Instance type: Free**.
3. **Змінні середовища (Environment Variables):**

   | Назва | Значення |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен бота |
   | `TELEGRAM_ADMIN_CHAT_ID` | твій ID |
   | `X_BEARER_TOKEN` | токен X |
   | `GITHUB_TOKEN` | токен із кроку 1 |
   | `GITHUB_STATE_REPO` | `iamlisaaay/Fan_bot_tg` |
   | `DEEPL_API_KEY` | ключ DeepL API Free (див. нижче) |

   **Чому DeepL:** безкоштовні перекладачі без ключа блокують сервери (Google відповідає Render `429`,
   а денний ліміт MyMemory спільний для всіх користувачів тієї ж адреси). Безкоштовний план
   [DeepL API](https://www.deepl.com/pro-api) працює з твоїм власним ключем. Ключ береться в акаунті
   DeepL, у розділі **API Keys**. Без ключа бот пробує Google, а потім MyMemory.

4. **Пінгер.** Безкоштовний Render засинає через 15 хвилин без запитів. На [cron-job.org](https://cron-job.org)
   створи завдання, яке кожні **10 хвилин** відкриває адресу сервісу (`https://….onrender.com/`).
   Сторінка просто відповідає `ok`.

Render дає 750 безкоштовних годин на місяць, а цілодобова робота займає до 744, тому інших безкоштовних
сервісів на Render у тебе бути не повинно, інакше години закінчаться раніше.

Поки працює Render, розклад GitHub Actions має бути вимкнений, інакше дві копії бота плутатимуть пам'ять.

## 6. Instagram на домашньому ПК (необов'язково)

Зараз Instagram не використовується: пости дублюються в X, а сторіс не публікуються. Цей крок потрібен, лише
якщо захочеш його ввімкнути, і тоді ПК має бути увімкнений.

1. Заведи окремий акаунт і дай йому кілька днів просто побути звичайним акаунтом.
2. Увійди в нього в окремому профілі браузера. Не виходь з акаунта, бо це скасує сесію.
3. Натисни F12, відкрий **Application → Cookies → instagram.com** і скопіюй `sessionid` і `csrftoken`
   у `.env` (`IG_SESSIONID`, `IG_CSRFTOKEN`), а логін — в `IG_USERNAME`.
4. Перевір (нічого не надсилається):

```bash
.venv\Scripts\python.exe -m bot --platforms instagram --dry-run
```

5. Постав автозапуск кожні 45 хвилин. Команду виконуй у папці проєкту у вікні `cmd`:

```bash
schtasks /create /tn "TG fan channel Instagram" /sc minute /mo 45 /tr "\"%cd%\run_instagram.bat\""
```

Журнал роботи: `logs/instagram.log`. Щоб оновлювати `config.yaml` в одному місці, правки роби на GitHub:
`run_instagram.bat` сам підтягує їх перед запуском.

## 7. Ручні пости через бота

Надсилаєш боту текст, фото, альбом, відео або файл. Він показує, як це виглядатиме, і чекає на кнопку
**Опублікувати**. Бот слухає лише твій `TELEGRAM_ADMIN_CHAT_ID`, усіх інших ігнорує.

Це працює на GitHub Actions разом із рештою, ПК не потрібен. Бот перевіряє повідомлення раз на 15 хвилин
(GitHub може запізнюватись), тому і чернетка, і публікація приходять не одразу. Термінове публікуй сама.

- Текст не українською бот сам доповнить перекладом.
- Якщо останній рядок — це лише посилання, він стане кнопкою «Дивитись».
- Щоб фото не стискались, надсилай їх боту **файлами**. У каналі вони теж вийдуть файлами.
- Жирний шрифт та інше форматування з твого тексту поки не зберігаються.
- Альбом, надісланий саме в момент перевірки, зрідка може розділитись на дві чернетки. Тоді скасуй їх і надішли ще раз.

## Як змінити сторінки

Відредагуй `accounts` у `config.yaml`. Прибери поле, щоб не стежити за платформою, або постав
`enabled: false`, щоб тимчасово вимкнути запис. Після змін на ПК зроби commit і push.

## Як бот уникає проблем

- **Перший запуск нічого не публікує.** Він лише запам'ятовує наявні пости, тож канал не засипле старим.
- **Без дублів.** Стан зберігається після кожного надісланого поста.
- **Нічого не губиться.** Якщо Telegram не прийняв пост, бот повторить спробу наступного разу.
  Якщо не вдалося надіслати медіа, піде текст із посиланням.
- **Пауза після блокування.** Бот не долбить платформу: він пише тобі й не чіпає її 6 годин
  (`block_cooldown_hours`). Якщо сесія Instagram злетіла, онови cookies у `.env` і видали
  `blocked_until` зі `state/instagram.json`.

## Обмеження

- Текст на самих фото та сторіс не розпізнається: перекладається лише підпис.
- Переклад машинний, сленг і жарти може передавати неточно.
- Транскрипція — це запис латиницею (наприклад, для корейської чи японської), а не розшифровка аудіо.
- Відео понад 50 МБ не влазить у Telegram, тоді замість нього йде прев'ю з посиланням.
- GitHub може запускати розклад із запізненням, а також вимикає його, якщо в репозиторії 60 днів не було
  активності.
